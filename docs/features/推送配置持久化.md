# 推送配置持久化功能

## 功能说明

easyGit 支持将推送配置(远程仓库和目标分支)持久化存储,避免每次推送都需要重新选择。首次推送时检测到多个远程会提示选择并保存,后续推送自动使用已保存的配置。

## 设计理念

### 问题

原始设计中,每次 `push-all` 或 `push-selected` 都会提示用户选择远程和分支:
- ❌ **重复操作** - 多远程场景下,每次推送都要选择
- ❌ **降低效率** - 增加不必要的交互步骤
- ❌ **用户体验差** - 99%的情况下选择相同的配置
- ❌ **单仓库限制** - 只支持单个远程推送

### 优化方案

**智能持久化 + 多远程并发**: 首次选择后自动保存,支持同时推送到多个远程
- ✅ **自动配置** - 多远程场景下首次推送提示选择并保存
- ✅ **自动使用** - 后续推送直接使用配置,无需重复选择
- ✅ **独立管理** - 提供 `set-push-config` 命令随时修改配置
- ✅ **信息提示** - 推送时显示正在使用的远程/分支
- ✅ **多远程支持** - 支持多选远程,一次推送到多个仓库
- ✅ **并发推送** - 使用 goroutine 并发推送,提升效率
- ✅ **仓库隔离** - 每个 Git 仓库独立配置,互不影响
- ✅ **性能优化** - 使用逗号分隔存储,避免 JSON 序列化开销

## 实现位置

- 配置存储: `internal/config/push_config.go` (全文件,使用逗号分隔存储)
- 智能选择: `internal/gitcmd/remote.go` (SelectRemoteWithConfig,支持多选)
- 集成到 push-all: `internal/gitcmd/pushAll.go` (推送段并行)
- 集成到 push-selected: `internal/gitcmd/pushSelected.go` (推送段并行)
- 集成到 tag-create/tag-delete/branch-delete: `internal/gitcmd/tag.go` / `internal/gitcmd/branch.go` (推送段并行,不再硬编码 origin)
- 并行执行器: `internal/command/progress_model.go` (NewProgressModelParallel / RunMultipleCommandsParallel,
  串行段逐条推进,到达 parallelFrom 后剩余步骤经 tea.Batch 一次性并发启动;
  并行段任一失败会等待其余在飞步骤结束,错误摘要列出全部失败步骤)
- 配置命令: `internal/config/option.go` 配置中心推送项 (原 set_push_config 已收敛)
- 数据库表: `settings` 表 (keys: push_remotes:/path/to/repo, push_branch:/path/to/repo)

## 运行流程

### 首次推送 (多远程场景)

```
用户执行 push-all
  ↓
选择提交类型
  ↓
输入提交信息
  ↓
【自动获取】获取当前分支名
  ↓
【自动检测】发现多个远程仓库
  ↓
【提示多选】"检测到多个远程仓库,请选择默认推送的远程 (支持多选)"
  用户选择: ☑ origin, ☑ github (支持空格多选)
  ↓
【自动保存】保存配置到数据库 (仓库独立,保存当前分支)
显示: "✅ 推送配置已保存: origin, github → main"
  ↓
执行 git add/commit
  ↓
【并发推送】执行 git pull (使用上游配置),然后并发 push 到 origin 和 github 的当前分支
显示: "📤 推送到 origin: main..."
显示: "📤 推送到 github: main..."
  ↓
显示: "✅ 推送成功: origin"
显示: "✅ 推送成功: github"
```

### 后续推送 (已有配置)

```
用户执行 push-all
  ↓
选择提交类型
  ↓
输入提交信息
  ↓
【自动获取】获取当前分支名
  ↓
【自动检测】发现已有配置 (origin, github)
  ↓
【无需选择】直接使用配置的远程仓库
显示: "📤 使用推送配置: origin, github → main"
  ↓
执行 git add/commit
  ↓
【并发推送】执行 git pull,并发 push 到 origin 和 github 的当前分支
```

## 配置/API

### 配置数据结构

```go
type PushConfig struct {
	Remotes []string // 远程仓库列表 (如 ["origin", "github"])
}
```

**重要变更**: 从 v1.x 开始,推送将自动使用当前分支,不再配置目标分支。Branch 字段已完全移除。

### 数据库 API

```go
// 获取推送配置 (仓库独立)
config, err := config.GetPushConfig()
// 返回: *PushConfig 或 nil (未配置)

// 保存推送配置 (只保存远程仓库列表)
err := config.SavePushConfig([]string{"origin", "github"})

// 清除推送配置
err := config.ClearPushConfig()
```

### 存储格式

```go
// ✅ 优化后: 逗号分隔 (性能更好)
remotesStr := strings.Join(remotes, ",")        // "origin,github"
remotes := strings.Split(remotesStr, ",")       // ["origin", "github"]

// ❌ 旧方案: JSON 序列化 (已弃用)
// remotesJSON, _ := json.Marshal(remotes)      // 慢
// json.Unmarshal([]byte(remotesJSON), &remotes)  // 慢
```

**性能对比**:
- 逗号分隔: 无需解析,直接字符串操作,速度快 10-100 倍
- JSON 格式: 需要编码/解码,分配内存,性能开销大

### Git 命令 API

```go
// 智能选择远程(支持配置和多选)
remotes, needSave, err := gitcmd.SelectRemoteWithConfig()
// 返回: []string (支持多个远程), needSave: true 表示需要保存配置

// 获取当前分支 (推送时使用)
currentBranch, err := gitcmd.GetCurrentBranch()

// 不持久化的选择(用于 set-push-config 命令)
remotes, err := gitcmd.SelectRemote()           // 多选远程
```

```bash
📤 推送到 github: main...
```


### 场景5: 仓库隔离

```bash

$ ./easyGit set-push-config

# 项目 B: /home/user/project-b
$ cd /home/user/project-b
$ ./easyGit set-push-config

✅ 推送配置已保存 (仅对 project-b 生效)

# 两个项目配置独立,互不影响
# project-a → origin, github (推送到当前分支)
# project-b → upstream (推送到当前分支)
```

## 注意事项

### 1. 配置存储位置

- 保存在 `~/.easyGit.db` 数据库的 `settings` 表
- 使用仓库绝对路径作为 key 前缀实现隔离
- Key 格式: `push_remotes:/absolute/path/to/repo`
- 值格式: 逗号分隔的字符串 (如 `"origin,github"`)

### 2. 仓库隔离机制

**工作原理**:
- 使用 `git rev-parse --show-toplevel` 获取仓库根目录绝对路径
- 每个仓库使用独立的数据库 key
- 不同项目的配置完全独立,互不影响

**示例**:
```
项目 A: /home/user/project-a
  Key: push_remotes:/home/user/project-a
  Value: origin,github

项目 B: /home/user/project-b
  Key: push_remotes:/home/user/project-b
  Value: upstream
```

### 3. 智能判断逻辑

**何时保存配置:**
- 检测到多个远程仓库,且用户首次选择
- 或检测到多个分支选项,且用户首次选择

**何时不保存配置:**
- 只有一个远程时(无需配置)
- 已有配置时(直接使用)

### 4. 多远程并发推送

**工作流程**:
1. 获取当前分支名
2. 执行 git pull (使用默认上游配置)
3. 并发推送到所有配置的远程的当前分支
4. 使用 goroutine 并发执行,提升速度
5. 收集所有错误,任一失败则报告

**性能优势**:
- 串行推送 3 个远程: 耗时 = T1 + T2 + T3
- 并发推送 3 个远程: 耗时 = max(T1, T2, T3)
- 典型场景可节省 50-70% 时间

**分支处理**:
- 总是推送到当前所在的分支
- 不同分支可以使用相同的远程配置
- 例如: main 分支推送到 origin/main, feature 分支推送到 origin/feature

### 5. 配置失效处理

如果配置的远程被删除:
- 自动清除配置
- 下次推送重新提示选择

### 6. 与 Git 原生配置的关系

easyGit 的配置**不影响** Git 原生配置:
- Git upstream 配置仍然有效
- `git push` 仍然使用 Git 原生行为
- easyGit 配置仅用于 `push-all` 和 `push-selected`

### 7. 配置优先级

```
SelectRemoteWithConfig 逻辑:
1. 检查是否只有一个远程 → 直接使用,不保存
2. 检查当前仓库的数据库配置 → 如存在且有效,使用配置
3. 提示用户多选 → 保存配置 (使用仓库路径作为 key)
```

## 数据库结构

### settings 表

```sql
CREATE TABLE IF NOT EXISTS settings (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

### 推送配置记录

```sql
-- 仓库 A 的远程配置 (逗号分隔)
INSERT INTO settings (key, value)
VALUES ('push_remotes:/home/user/project-a', 'origin,github');

-- 仓库 B 的远程配置
INSERT INTO settings (key, value)
VALUES ('push_remotes:/home/user/project-b', 'upstream');

-- 查询配置 (使用仓库路径)
SELECT value FROM settings WHERE key = 'push_remotes:/home/user/project-a';
-- 返回: "origin,github"

-- 清除配置
DELETE FROM settings WHERE key = 'push_remotes:/home/user/project-a';
```

## 用户体验优化

### 1. 减少交互次数

**优化前 (每次推送)**:
1. 选择提交类型
2. 输入提交信息
3. 选择远程仓库 ← 重复
4. 选择目标分支 ← 重复

**优化后 (首次推送)**:
1. 选择提交类型
2. 输入提交信息
3. 选择远程仓库 (首次)
4. 选择目标分支 (首次)

**优化后 (后续推送)**:
1. 选择提交类型
2. 输入提交信息
3. (自动使用配置)

### 2. 信息提示清晰

- ✅ 首次选择:"检测到多个远程仓库,请选择**默认推送的**远程"
- ✅ 配置保存:"✅ 推送配置已保存: origin → main"
- ✅ 使用配置:"📤 推送到: origin/main"
- ✅ 修改提示:"💡 使用 'set-push-config' 修改配置"

### 3. 灵活性

- 随时查看配置: `set-push-config`
- 随时修改配置: `set-push-config`
- 随时清除配置: `set-push-config clear`

## 扩展方向

### 1. 多配置文件支持

```bash
# 为不同项目使用不同配置
easyGit set-push-config --project myproject

# 当前项目: upstream/develop
# 其他项目: origin/main
```

### 2. 分支关联

```bash
# 为不同本地分支配置不同的推送目标
# feature/* → upstream/develop
# hotfix/* → origin/main
```

### 3. 配置模板

```bash
# 预设常用配置
easyGit set-push-config --template fork-workflow
# 自动配置: origin/feature-branch
```

```bash
# 导出配置
easyGit export-config > .easyGit-config.json

# 导入配置(团队共享)
easyGit import-config .easyGit-config.json
```
