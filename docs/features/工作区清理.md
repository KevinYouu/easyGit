# 工作区清理(cl)

## 功能说明

`clean (cl)`:交互式工作区清理。单一多选列表混合呈现两类条目(标注类别):

- `[已修改] path` - 已跟踪文件的修改(含暂存与未暂存),选中后还原到 HEAD
- `[未跟踪] path` - 未跟踪文件,选中后物理删除

统一强确认(逐类计数 + 完整文件清单)后分组执行;干净仓库直接提示退出。

## 设计理念

### 问题

- ❌ `git restore --staged --worktree .` / `git checkout -- .` 一把梭,无法挑选
- ❌ `git clean -fd` 太危险不敢用;逐文件手敲 `rm` 繁琐且易删错
- ❌ 两类清理分属不同命令,没有统一的"看看再删"入口

### 优化方案

- ✅ **单列表双类别** - 一次浏览、一次勾选、一次确认,Space 切换 `/` 过滤可用
- ✅ **类别标注** - 每行前缀标注「已修改/未跟踪」,执行语义一目了然
- ✅ **忽略项保护** - `ls-files --exclude-standard`,gitignore 忽略的文件不列出也不删除
- ✅ **删除场景覆盖** - 还原已跟踪文件同时恢复"已提交后手动删除"的文件
- ✅ **破坏性确认** - 确认框完整列出将销毁的全部路径

## 测试

真实 git 仓库集成回归:

- 列表:暂存与未暂存均入已修改列表;未跟踪不含已跟踪与 gitignore 忽略项;干净仓库两列表为空
- 还原:内容回 HEAD、暂存清空、被删除文件恢复
- 删除:未跟踪文件从磁盘移除
- 流程注入:混合选择同时生效两类 / 确认取消零改动 / 干净仓库不出列表

## 注意事项

- 空仓库(无 HEAD)时 `diff HEAD` 失败视为无已跟踪修改,优雅降级仅处理未跟踪项
