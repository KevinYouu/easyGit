# 功能特性：提交合并 (Squash)

## 背景

在日常开发中，开发者经常会产生许多细碎的本地提交（例如 "fix typo", "wip", "update" 等）。在将这些更改推送到远程仓库或合并到主分支之前，将这些零碎的提交合并为一个清晰、完整的提交是一个良好的实践。

原生的 `git rebase -i` 虽然强大，但交互复杂且容易产生冲突。`easyGit` 提供的 `squash` 功能旨在提供一种更简单、更安全的合并体验。

## 设计理念

- **直观性**：采用“所选即所得”的模式。用户在提交历史列表中选择一个提交，该提交及其之后的所有提交都会被合并。
- **安全性**：通过 `git reset --soft` 实现。由于它只是移动 HEAD 指针并保留暂存区内容，因此绝对不会产生合并冲突。
- **简易性**：一键打包，一键重新提交。

## 操作流程

1. **启动命令**：运行 `easyGit squash` 或简写 `easyGit sq`。
2. **选择范围**：在交互式表格中选择要合并的**最早**的一个提交。
   - 选中的提交及其之后（上方）的所有提交都将被合并。
   - 列表中会标记 `[HEAD]` 以示当前位置。
3. **输入信息**：输入合并后新提交的提交信息。
   - 默认会带入原 `HEAD` 的提交信息。
4. **自动执行**（交互式变基 + 拦截器）：
   - `GIT_SEQUENCE_EDITOR` 注入隐藏子命令 `_internal_rebase_editor` 自动重写变基计划（`reword` + `fixup`）。
   - `GIT_EDITOR` 注入临时消息脚本（Windows 为 `.bat`，其他平台为 `.sh`），自动写入合并消息。
   - 可执行文件路径与脚本路径统一经 `QuoteForEditorEnv` 双引号转义，兼容含空格的 Windows 安装路径（如 `C:\Program Files\...`）。
5. **特殊情况处理**：
   - 选择到仓库第一个提交（初始提交）时，程序自动使用 `--root` 模式，确保合并操作依然有效。

## 与原生命令对比

| 维度 | Git 原生 (rebase -i) | easyGit (squash) |
| --- | --- | --- |
| **学习成本** | 高 (需要了解多种操作指令) | 极低 (点选即可) |
| **冲突风险** | 有 (重放提交时可能冲突) | 低 (拦截器重写计划,冲突时进入解决闭环) |
| **灵活性** | 极高 (可删减、排序) | 中 (仅限连续合并) |
| **交互速度** | 慢 (打开编辑器) | 快 (实时表单 + 自动注入消息) |

## 总结

`easyGit squash` 是为了解决“清理本地历史”这一高频需求而设计的。它牺牲了一部分 `rebase` 的复杂灵活性，换取了 100% 的成功率和极速的操作体验，非常符合 `easyGit` 简化 Git 工作流的核心宗旨。
