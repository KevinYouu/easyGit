# 功能特性：提交合并 (Squash)

## 背景

在日常开发中，开发者经常会产生许多细碎的本地提交（例如 "fix typo", "wip", "update" 等）。在将这些更改推送到远程仓库或合并到主分支之前，将这些零碎的提交合并为一个清晰、完整的提交是一个良好的实践。

原生的 `git rebase -i` 虽然强大，但交互复杂且容易产生冲突。`easyGit` 提供的 `squash` 功能旨在提供一种更简单、更安全的合并体验。

## 设计理念

- **直观性**：采用“所选即所得”的模式。用户在提交历史列表中勾选要合并的**连续**提交，一次确认完成。
- **不丢信息**：合并后的提交信息默认完整保留所选提交的**主题与正文**（换行与空行原样保留），不会退化为单行主题。
- **安全性**：合并经由交互式变基完成；冲突时进入统一的冲突解决闭环，不留下半成品状态。
- **简易性**：一键打包，表单内编辑消息，无需进入 Vim 等编辑器。

## 操作流程

1. **启动命令**：运行 `easyGit squash` 或简写 `easyGit sq`。
2. **选择范围**：在交互式列表中多选要合并的提交（Space 勾选，`/` 过滤）。
   - 至少选择 2 个，且必须是**连续**提交（不连续会提示并退出）。
   - 列表中会标记 `[HEAD]` 以示当前位置。
3. **编辑信息**：多行文本表单预填合并后的提交信息。
   - 默认值为所选提交的消息按**从旧到新**拼接，每条消息（主题 + 正文）之后空一行，与 `git rebase -i` 原生 squash 的拼接结果一致。
   - 表单内可直接编辑：`Enter` 提交、`ctrl+j`（或 `alt+enter`）插入换行、`Esc` 取消。
   - 打开表单时光标与视图停在**第一行**（长消息不会只看到末尾几行），向下滚动查看其余内容；提交的是完整文本，不是可视区内容。
   - 空白消息会被拒绝（提交信息不能为空）。
4. **自动执行**（交互式变基 + 拦截器）：
   - `GIT_SEQUENCE_EDITOR` 注入隐藏子命令 `_internal_rebase_editor` 自动重写变基计划（首个提交 `reword` + 其余 `fixup`）。
   - `GIT_EDITOR` 注入隐藏子命令 `_internal_commit_message_editor`：读取环境变量 `EASYGIT_COMMIT_MESSAGE`，把消息**整体**写入 git 传入的消息文件。
   - 消息不经 shell 解释（无临时脚本、无 `echo`、无转义表），因此多行正文、空行、`$`/`` ` ``/`&` 等字符在 Linux、macOS、Windows 上都原样落盘。
   - 变基以 `git -c commit.cleanup=verbatim rebase -i` 执行：git 默认的 `strip` 清理会删除所有以 `#` 开头的行（Issue 号、模板说明）并压缩空行，主题被删空时还会直接提交失败；`verbatim` 保证表单里的文本一字不差地成为提交信息。
   - 可执行文件路径经 `QuoteForEditorEnv` 双引号转义，兼容含空格的 Windows 安装路径（如 `C:\Program Files\...`）。
5. **特殊情况处理**：
   - 选择到仓库第一个提交（初始提交）时，程序自动使用 `--root` 模式，确保合并操作依然有效。

## 与原生命令对比

| 维度 | Git 原生 (rebase -i) | easyGit (squash) |
| --- | --- | --- |
| **学习成本** | 高 (需要了解多种操作指令) | 极低 (勾选即可) |
| **冲突风险** | 有 (重放提交时可能冲突) | 低 (拦截器重写计划,冲突时进入解决闭环) |
| **灵活性** | 极高 (可删减、排序) | 中 (仅限连续合并) |
| **消息保留** | 逐条编辑 todo 与消息 | 默认保留全部原文,多行表单内编辑 |
| **交互速度** | 慢 (打开编辑器) | 快 (实时表单 + 自动注入消息) |

## 总结

`easyGit squash` 是为了解决“清理本地历史”这一高频需求而设计的。它牺牲了一部分 `rebase` 的复杂灵活性，换取了 100% 的成功率和极速的操作体验，非常符合 `easyGit` 简化 Git 工作流的核心宗旨。
