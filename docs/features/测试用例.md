# 测试用例文档

## 功能说明

本文档记录 easyGit 项目的测试用例实现,包括各个模块的测试覆盖率和测试策略。

## 实现位置

测试文件分布在各个包的 `*_test.go` 文件中:

- `internal/gitcmd/branch_test.go` - 分支操作测试
- `internal/gitcmd/merge_test.go` - 合并操作测试
- `internal/gitcmd/reset_test.go` - 重置操作测试
- `internal/gitcmd/tag_test.go` - 标签操作测试
- `internal/gitcmd/stats_test.go` - 统计功能测试
- `internal/form/form_test.go` - 表单组件逻辑测试(输入验证、默认值)
- `internal/form/render_test.go` - 表单基础组件渲染测试(Select/MultiSelect/TableSelect/TableMultiSelect + 共享辅助函数)
- `internal/form/render_command_test.go` - 命令表单渲染测试(全部 Select/MultiSelect/Table 调用点)
- `internal/form/render_input_confirm_test.go` - 输入框/确认框渲染测试(全部 Input/Confirm 调用点)
- `internal/command/progress_model_test.go` - 进度条模型测试(含 View 渲染)
- `internal/config/config_test.go` - 配置管理测试
- `internal/i18n/i18n_test.go` - 国际化测试
- `internal/testutil/git_helper.go` - 测试辅助工具

## 测试用例详解

### 1. gitcmd 包测试

#### branch_test.go

测试分支相关功能:

- `TestGetCurrentBranch` - 获取当前分支
- `TestGetCurrentBranch_NotGitRepo` - 非 Git 仓库错误处理
- `TestGetAllBranches` - 获取所有分支
- `TestGetAllBranches_EmptyRepo` - 空仓库处理
- `TestGetAllBranches_NotGitRepo` - 非 Git 仓库错误处理

**实现位置**: `internal/gitcmd/branch_test.go:11-114`

#### merge_test.go

测试合并相关功能:

- `TestGetCurrentBranch_Merge` - 合并时获取当前分支
- `TestGetLocalBranches` - 获取本地分支列表
- `TestGetLocalBranches_OnlyCurrentBranch` - 只有当前分支的情况
- `TestCheckWorkingDirectoryStatus_Clean` - 工作目录干净状态检查
- `TestMergeStrategy_DefaultValues` - 合并策略配置验证
- `TestGetRemoteBranches_NoRemote` - 无远程仓库处理

**实现位置**: `internal/gitcmd/merge_test.go:12-144`

#### reset_test.go

测试重置相关功能:

- `TestCommit_Structure` - Commit 结构体验证
- `TestGetModeDescription` - 重置模式描述
- `TestCommit_TimestampParsing` - 时间戳解析
- `TestCommit_MessageTruncation` - 提交消息截断

**实现位置**: `internal/gitcmd/reset_test.go:8-78`

### 2. form 包测试

#### form_test.go

测试表单组件的逻辑部分:

- `TestInput_Validation` - 输入验证逻辑
- `TestConfirm_DefaultValue` - 确认框默认值
- `TestInput_DefaultValue` - 输入框默认值
- `TestInput_EmptyString` - 空字符串验证
- `TestInput_ValidString` - 有效字符串验证
- `TestConfirm_BooleanValue` - 布尔值处理

**实现位置**: `internal/form/form_test.go:8-102`

#### render_test.go(基础组件渲染)

通过真实 huh 表单模型 + `tea.WindowSizeMsg` 驱动渲染,验证高度自适应与内容驱动布局:

- `TestSelectRenderUsesAllSpace` - 单选列表按内容计算高度
- `TestSelectRenderManyOptions` - 大量选项时高度封顶
- `TestMultiSelectRenderUsesAllSpace` - 多选列表高度自适应
- `TestTableSelectRender` - 单选表格渲染
- `TestTableMultiSelectRender` - 多选表格渲染

共享辅助函数: `renderSelectField`、`renderMultiSelectField`、`visibleLabels`、`assertTableView`、`tableSizes`(8 种终端尺寸)、`commitLabels`、`testOptions`。

#### render_command_test.go(命令调用点渲染)

覆盖全部命令的实际 Select/MultiSelect/Table 表单调用点:

- `TestCommandSelectRender` - 11 个命令的单选表单(含 merge/rebase 目标分支列表), 高度 `[24,12,10,8,6]`
- `TestCommandMultiSelectRender` - 4 个命令的多选表单(含 remote 远程仓库列表)
- `TestCommandTableRender` - drop/squash 多选表格、reset 列表、reset 模式
- `TestTableListLongMessageSingleLine` - 列表超长省略: 验证使用仓库 `SafeTruncate` 的 `...` 而非 bubbles 回退的 `…`, 覆盖单选/多选两种模型

关键断言 `assertCommandField`: 总高度 = `min(选项数+1, 终端高度)`, 行不越界。

#### render_input_confirm_test.go(输入/确认渲染)

- `TestCommandInputRender` - 5 个命令的输入框(push-all 默认 `fix: `、push-selected `feat: `、squash 旧提交消息、tag 版本号自增、tag 提交消息)
- `TestCommandConfirmRender` - 6 个命令的确认框(分支删除、分支远程删除、drop `5 个提交`、merge continue、reset 两行、tag 删除两行)

关键断言 `assertCompactField`: 标题行存在、总高度不超过终端、无尾部空行、无宽度溢出。

**实现位置**: `internal/form/render_test.go`、`internal/form/render_command_test.go`、`internal/form/render_input_confirm_test.go`

### 3. command 包测试

#### progress_model_test.go

进度条模型渲染测试:

- 初始状态: 步骤描述 + `(0/3)` + 3 个未完成圆点
- 进度条宽度自适应: 宽度 `[80,50,40,30,24]` 下进度条 ≤ 40 列且所有行不越界
- 状态图标切换: ✓/▶/⚡ 与 ✓×3/✅/❌

**实现位置**: `internal/command/progress_model_test.go`

提供测试辅助函数:

- `RunGitCommand(t, dir, args...)` - 执行 Git 命令

## 测试策略

### 单元测试原则

1. **隔离性** - 每个测试独立运行,使用临时目录
2. **可重复性** - 测试结果稳定,不依赖外部状态
3. **清晰性** - 测试名称明确表达测试意图
4. **完整性** - 覆盖正常情况和边界情况

### Git 操作测试

对于 Git 操作测试:

1. 使用 `testutil.CreateTempGitRepo()` 创建临时仓库
2. 在测试结束后自动清理临时文件
3. 配置测试用户信息避免 Git 配置依赖
4. 测试正常流程和错误处理

### 交互式组件测试

对于交互式 UI 组件(form, progress):

1. 使用真实 huh 表单模型 + `tea.WindowSizeMsg` 消息驱动渲染,断言渲染结果
2. 覆盖所有命令的实际调用点(Select/MultiSelect/Input/Confirm), 防止表单配置回归
3. 覆盖多种终端尺寸(24 行到 60 行、24 列到 300 列), 验证高度自适应与不越界
4. 进度条使用 `NewProgressModelWithoutSpinner` 保证图标确定性
5. UI 逻辑(动画时序等)通过手动测试

渲染级测试要点:

- `tea.View.Content` 获取纯文本渲染结果
- 高度断言用行数, 宽度断言用 `ansi.Strip` 去除 ANSI 后按 rune 计数(进度条 `░`/`█` 为 3 字节 UTF-8)
- 下拉列表高度公式 `min(选项数+1, 终端高度)`, 表格高度 `max(高度-3, 3)` 且不超过选项数
- Input/Confirm 无显式高度, 内容高度固定, 任何终端高度都满足

## 注意事项

1. **测试隔离** - 每个测试使用独立的临时 Git 仓库
2. **清理资源** - 使用 `t.TempDir()` 自动清理临时文件
3. **错误处理** - 测试同时验证成功和失败场景
4. **跨平台** - 测试代码在 Linux/macOS/Windows 上均可运行
5. **Git 版本** - 某些测试依赖 Git 2.28+ (主要是 init.defaultBranch 配置)
