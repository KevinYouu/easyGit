# 合并/摘取冲突闭环(通用冲突解决)

## 功能说明

将变基的冲突解决闭环推广为**通用实现**,`merge (m)` 与 `cherry-pick (cp)` 冲突时不再打印提示后退出,而是进入与 `rebase (r)` 一致的循环菜单:

- 打开编辑器解决冲突
- 已解决,继续(`git add` + `--continue`)
- 跳过当前提交(cherry-pick 支持;merge 无此能力自动隐藏)
- 中止操作(`--abort`,恢复操作前状态)
- 退出保持挂起

多提交/多次冲突场景下自动循环,直到操作完成或用户中止。

## 设计理念

### 问题

- ❌ 体验不一致:rebase 撞冲突有闭环,merge/cherry-pick 只打印 "use git status" 就退出
- ❌ cherry-pick 批量摘取多个提交时,第一个冲突就终止整个批次
- ❌ 三处各自维护冲突处理代码,行为漂移

### 优化方案

- ✅ **单一实现** - `conflictOps` 配置结构 + `runConflictResolution` 驱动,三种操作共用一套菜单/编辑器/标记检测逻辑
- ✅ **能力自适应** - `skipCmd=nil` 时菜单自动隐藏 skip(merge 无 --skip)
- ✅ **批次语义** - 用户主动中止返回 `errConflictAborted`,cherry-pick 批次优雅停止且不报错;退出挂起仍视为错误
- ✅ **策略记忆不丢** - merge 经闭环完成合并后同样记忆本次合并策略

## 实现位置

| 职责 | 文件 |
| --- | --- |
| 通用闭环与共享工具 | `internal/gitcmd/conflict.go`(conflictOps / runConflictResolution / getUnmergedFiles / openConflictsInEditor / resolveConflictEditor / hasUnresolvedMarkers / 状态检测)|
| rebase 接入 | `internal/gitcmd/rebase.go`(handleRebaseConflict 薄封装,rebaseConflictOps)|

## 测试

真实 git 仓库集成回归:

- 状态检测:MERGE_HEAD / CHERRY_PICK_HEAD 存在性判定
- merge 闭环:解决后 continue 完成合并(合并提交生成、内容为解决值)/ abort 恢复现场 / 无 skip 选项断言
- cherry-pick 闭环:skip 放弃提交且状态清理 / executeCherryPick 解决路径返回 nil / abort 返回 errConflictAborted 且状态清理
- 既有 rebase 多冲突循环回归全部保留(withConflictMenu 注入签名升级)

## 注意事项

- `runConflictResolution` 返回 `(aborted bool, err error)`:aborted=true 表示用户主动中止(已回滚),调用方应停止后续批次;quit 保持挂起仍返回错误
- `--continue` 统一注入 `GIT_EDITOR=true` 接受预设提交信息,防止非交互环境挂起
