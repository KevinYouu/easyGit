# 变基冲突解决闭环

## 功能说明

`easyGit rebase`（标准变基）与 `squash` / `drop`（交互式变基）遇到冲突时，不再打印提示后退出，而是进入**冲突解决闭环**：工具内循环展示冲突文件与操作菜单，直到变基完成、跳过、中止或用户主动退出。

## 设计理念

### 问题

原实现中，冲突后的流程是断裂的：

- ❌ **冲突即退出** - `git rebase` 检测到冲突只打印"请手动解决冲突"就返回
- ❌ **多冲突无法闭环** - 多个提交依次冲突时，每次 `--continue` 后再次冲突都会退出工具，用户需要反复手动处理并重新进入
- ❌ **冲突文件不可见** - 工具内无法直接看到未合并文件清单
- ❌ **squash/drop 无恢复入口** - 交互式变基冲突后只能靠重跑 `easyGit r` 进入恢复菜单

### 优化方案

**冲突解决闭环**：冲突后进入循环，工具内完成「查看冲突 → 编辑 → 继续/跳过/中止」全流程

- ✅ **冲突文件清单** - 进入闭环时展示 `git diff --diff-filter=U` 的未合并文件
- ✅ **一键打开编辑器** - 按配置中心「冲突编辑器」设置启动（未设置时 `$EDITOR`/`$VISUAL`，回退 vim/vi/nano），无编辑器时展示清单提示手动编辑
- ✅ **自动循环** - continue/skip 后检查变基状态，仍有冲突自动回到菜单（多提交多冲突一次搞定）
- ✅ **操作完整** - 继续（自动 `git add` + `--continue`）/ 跳过 / 中止 / 退出保持挂起
- ✅ **三入口统一** - 标准变基、进行中恢复菜单、squash/drop 共用同一闭环
- ✅ **编辑器防挂起** - `--continue` 注入 `GIT_EDITOR=true`：非 TTY 环境下 git 也会启动编辑器获取提交信息，pick 提交直接接受原始信息、reword 接受工具内已注入的消息，避免流程挂起
- ✅ **逃生口保留** - 可随时退出，变基保持挂起状态，稍后手动或再进工具继续

## 实现位置

- 冲突闭环: `internal/gitcmd/rebase.go` (`handleRebaseConflict` / `getUnmergedFiles` / `runGitRebaseContinue` / `openConflictsInEditor` / `rebaseConflictMenu` 注入点)
- 编辑器配置: `internal/config/conflictEditor.go` (GetConflictEditor/SaveConflictEditor, settings 表 `conflict_editor` 键) / `cmd/easygit/commands/config_conflict_editor.go` (配置中心子流程)
- 三入口接入: `handleStandardRebase` / `handleInProgressRebase` / `RunInternalRebase`(squash/drop 共用)
- 检测增强: `handleRebaseError` 冲突判定以 `isRebaseInProgress()`(rebase-merge/rebase-apply 目录)为主
- i18n: `rebase.conflict.menu.*` / `rebase.conflict.files` 等键(zh/en)
- 测试: `internal/gitcmd/rebase_test.go` (菜单注入驱动真实 git 仓库)

## 测试

- `TestIsRebaseInProgress` / `TestGetUnmergedFiles` - 冲突状态与未合并文件检测
- `TestHandleRebaseConflictMultiConflictLoop` - **核心回归**:两个提交依次冲突，第一次 continue 后自动循环，第二次解决后完成（验证"第一次冲突后即退出"已修复）
- `TestHandleRebaseConflictSkip` / `TestHandleRebaseConflictAbort` / `TestHandleRebaseConflictQuit` - 跳过/中止/挂起路径

## 注意事项

- 编辑器打开为外部进程（lazygit 同款方案），会短暂离开 TUI；不做图形化 merge 编辑器
- `git add` 会暂存全部未合并文件；仍含冲突标记(`<<<<<<<`/`>>>>>>>`)的文件会先弹确认，确认后才按当前内容暂存
- **GIT_EDITOR=true 行为**：冲突后 `--continue` 一律注入 `GIT_EDITOR=true`（非 TTY 下 git 也会启动编辑器，导致流程挂起）。pick 提交直接接受原始信息；若变基计划含 `reword` 提交，其消息编辑会被跳过——easyGit 生成的 squash 流程消息已预先注入所以不受影响；手动构造含 reword 的变基计划需注意此行为

## 编辑器支持

| 编辑器 | 配置值 | 说明 |
| ------ | ------ | ---- |
| VS Code | `code -w` | 或直接 `code`（自动补 `-w` 等待标志）；关闭窗口后回到菜单 |
| Sublime Text | `subl` | 自动补 `-w` |
| Atom | `atom` | 自动补 `-w` |
| vim / vi / nano | `vim` 等 | 前台等待退出 |
| Windows notepad | 自动回退 | 无等待标志，经 `start /wait` 逐个打开 |

- **Windows 环境**：vim 随 Git for Windows 提供；nano/vi 需自行安装；notepad 为系统自带回退
- **带空格路径**：用引号包裹，如 `"C:\Program Files\Microsoft VS Code\code.exe"`
