# 单页多输入表单(MultiInput)

## 功能说明

`tc`(tag-create)需要连续收集「版本号」与「提交消息」两个输入。此前用两次 `form.Input` 连续弹两个内联表单,第二个表单渲染在第一个残留内容的下方,终端同时显示两页输入。

**根因**:Input/Confirm 是内联模式(非 AltScreen);bubbletea v2 内联程序退出时,`cursedRenderer.close()` 只把光标移到帧底并 `EraseScreenBelow`,**帧内容留在主屏**;下一个表单是新 tea 程序,渲染器从当前光标位置开画且不清屏 → 上下堆叠。全库仅 `tc` 是 Input→Input 连续内联,其他命令的 Input 都跟在 AltScreen 列表之后(退出 alt 屏恢复干净主屏),故只有 tc 受影响。

**方案**:huh v2 原生支持单页多字段——`huh.NewGroup(fields...)` 将多个字段堆叠渲染在同一页。两个输入合并为**同一页上下两个输入框**(单 tea 程序 → 单渲染器 → 正确重绘,无堆叠),保持 Input 内联设计不变。

## 实现位置

- 组件: `internal/form/input.go`(`InputSpec` / `NewMultiInputForm` / `MultiInput`,输入字段经 `newInputField` 与 `NewInputForm` 共用构造路径)
- 帮助栏键位: `internal/form/helpbar.go`(`multiInputHelpKeys`:Enter 继续/提交、Shift+Tab 上一步、Esc 取消)
- i18n: `internal/i18n/en.go` / `zh.go`(`form.help.next` = Next/Submit / 继续/提交、`form.help.prev` = Back / 上一步)
- 调用方: `internal/gitcmd/tag.go`(`CreateAndPushTag` 一次 `form.MultiInput` 收集两个值)

## 设计要点

### 接口

```go
// InputSpec 单页多输入表单的一项:标题与默认值
type InputSpec struct {
    Title   string
    Default string
}

// MultiInput 单页收集多个输入,返回结果与 specs 一一对应;
// 错误处理与 Input 一致(取消时上抛 ErrUserAborted)。
func MultiInput(specs []InputSpec) ([]string, error)
```

- 空 specs 直接返回空结果(构造前置守卫,避免 `huh.NewGroup()` 空字段组)
- 默认值播种:调用方无需预写指针,`MultiInput` 内部按 `spec.Default` 初始化

### 键位语义(huh 默认键位经 `WithPosition` 按字段位置启停)

- 字段 1 按 Enter/Tab → 非空校验通过后 `NextField` 跳到字段 2;空输入不推进并显示错误
- 字段 2(末字段)按 Enter → 校验后提交整个表单
- Shift+Tab → 回退到上一字段
- Esc / Ctrl+C → 取消(与单输入一致)

### 渲染

- 所有字段放入**一个** `huh.NewGroup(fields...)`,经现有 `newForm` 包装(Quit=ctrl+c/esc、`WithShowHelp(false)`),`dividerAfterTitle=false`(标题下方无分隔线)
- **卡片化统一容器**(`theme.GetMultiInputTheme`):每个字段都是带边框卡片(边框 + 左右留白),焦点卡片边框高亮 `PrimaryColor`、标题加粗,模糊卡片边框 `BorderColor`、标题弱化;两态尺寸完全一致,Enter 切换焦点**零布局跳变**(修复旧版焦点无框/模糊有框的不一致)
- **序号标题**:字段标题前加标准数字序号(`1.`、`2.`…,渲染层装饰,不进 i18n),聚焦时与标题同加粗高亮
- **提示符统一 `❯`**(`newInputField` 的 `Prompt("❯ ")`,与列表选中指示符一致),焦点加粗白、模糊弱化
- **字段描述**:`InputSpec.Desc` 渲染为标题下弱化提示行(如「自动递增自最新标签,可修改」),空串不显示
- **错误提示**:空值 Enter 后在底部渲染红色加粗 `✗ 输入不能为空`(ErrorColor + ✗ 图标)
- 自然高度:带描述 13 行(2×5 卡片 + 空行 + 分隔线 + 帮助栏)、无描述 11 行;终端高度不足时 huh 自底部裁剪视图(正常行为),≥13 行完整渲染
- 帮助栏为静态文案:`[Enter] 继续/提交`、`[Shift+Tab] 上一步`、`[Esc] 取消`,键值对间 `·` 分隔(Enter 在非末字段为"继续"、末字段为"提交",文案不随焦点变化)
- 帮助栏为静态文案:`[Enter] 继续/提交`、`[Shift+Tab] 上一步`、`[Esc] 取消`(Enter 在非末字段为"继续"、末字段为"提交",文案不随焦点变化)

### 与单输入的一致性

- 同一 `newInputField` 构造闭包:占位符、非空校验(仅 `str == ""` 判空,空格不算空)统一配置,防止两份漂移
- 生产(`Form.Run`)与渲染测试共用 `NewMultiInputForm` 构造路径

## 运行流程

```
tc 命令触发
  ↓
CreateAndPushTag 调用 form.MultiInput(specs)  ← 一次调用,一个表单
  ↓
单页渲染:版本号输入框 + 提交消息输入框 上下堆叠
  ↓
字段 1 Enter → 校验非空 → 焦点到字段 2
字段 2 Enter → 提交 → 返回值数组 [version, commitMessage]
Esc / Ctrl+C → 取消(ErrUserAborted 上抛)
  ↓
version / commitMessage 组装 git tag 命令并执行
```

## 注意事项

1. **修复粒度**:单 tea 程序单渲染器是消除堆叠的关键,禁止再拆成多次 `form.Input` 连续调用
2. **帮助栏静态文案**:Enter 键动作随焦点位置变化(继续/提交),帮助栏文案固定写「继续/提交」,不逐字段切换
3. **极小终端**:带描述自然高度 13 行,huh 自底部裁剪;首次字段始终可见(位于最上),末字段需终端 ≥8 行才显示标题
4. **默认值语义**:版本号自动递增作字段 1 默认值,Enter 可直接跳过;提交消息无默认值,必须输入
5. **i18n**:标题、占位符、空值错误、帮助栏文案全部经 `i18n.T`,中英文键同步维护
