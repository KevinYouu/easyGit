# 高频 Git 命令覆盖缺口分析

## 结论摘要

`easyGit` 目前覆盖「提交/推送、历史整理、分支、标签、stash、worktree、配置」七类操作，
`easyGit` 无参数菜单即可完成日常大部分流程。但按真实使用频次排序，仍有 **5 个高频场景没有入口**，
其中 P0 的两项属于「必须退回原生 git」的硬缺口：

| 优先级 | 缺口 | 现状（证据） | 用户退回 git 的场景 |
| --- | --- | --- | --- |
| P0 | 独立 `pull` / `fetch` | `git pull` 仅作为 pa/ps 的可选串行步骤（`internal/gitcmd/pushAll.go:122`），全库没有 `fetch` | 只想同步远端、不想提交任何东西 |
| P0 | 独立 `push`（已有提交） | pa/ps 固定 `add -A → commit -m → (pull) → push`（`pushAll.go:94/101/133`） | 提交已经在本地历史里，只想推上去 |
| P1 | `revert`（反向提交） | `undo` 走 reflog、`reset` 移动 HEAD、`drop` 改写历史，都是本地重写；无 `revert` | 已推送/共享分支上的错误提交需要回滚 |
| P1 | 多行提交信息（正文） | pa/ps/am 用单行 `form.InputWithSuggestions`（`pushAll.go:67`、`pushSelected.go:70`、`amend.go:46`） | 提交需要写正文、Issue 号、变更说明列表 |
| P2 | `status` / `diff` 查看 | 只有 `ps` 的文件状态列表（`internal/gitcmd/stats.go`），无 diff 预览、无历史浏览入口 | 提交前先看改了什么 |
| P2 | `remote` 管理 | `internal/gitcmd/remote.go` 只读（`GetAllRemotes` 等），无 add / set-url / remove | 首次绑定远端、远端地址变更 |
| P3 | 分支改上游 | 仅 `branch-create` 用 `push -u`（`internal/gitcmd/branch_create.go:73`） | 已有分支切远端或修正 upstream |
| P3 | 标签补推 / 列表 | `tag-create` 创建即推、`tag-delete` 删除即推；无「推送已有本地标签」与标签列表 | 本地已打标签但没推、想先看一眼远端标签 |

## 已知硬伤：pa 在干净工作区必然失败

`pa`/`ps` 把 `git commit` 作为固定步骤，工作区无改动时 `git commit` 返回非零，
`RunMultipleCommandsParallel`（`internal/command/progress_model.go:496`）整体报错并终止，
后续 `pull`/`push` 都不会执行。也就是说：**工作区干净时，easyGit 没有任何方式把本地提交推上去**。
P0 的「独立 push」不只是便利性功能，而是当前流程的兜底缺失。

## 建议方案（按优先级）

### P0-1 同步：`easyGit sync`（或 `pull`）

- 交互：默认对当前分支执行 `fetch --prune` → `pull --ff-only`；上游冲突/分叉时列出 `rebase`/`merge` 两个选项复用现有冲突闭环。
- 复用：`shouldPullBeforePush`（`pushAll.go:38`）的 upstream 判定；`splitUpstreamRef` 解析 remote/branch。
- 风险：`--ff-only` 失败要给出可执行的下一步，而不是直接抛 git 输出。

### P0-2 推送：`easyGit push`（不提交）

- 交互：展示待推送提交（`git log @{u}..HEAD --oneline`）→ 选择 remote（复用 `SelectAndSaveRemotes`）→ 推送当前分支。
- 无 upstream 时提示并走 `push -u`；无待推送提交时给出明确提示而非报错。
- 同时修 `pa`/`ps`：`git add -A` 后无改动则跳过 commit 步骤直接进入 pull/push（进度屏步骤动态生成）。

### P1-1 回滚：`easyGit revert`

- 交互：复用 `GetCommitsOptions` 的提交多选列表（与 `sq`/`d` 同一数据源），按从旧到新逐个 `git revert --no-edit`（或单条合并 `-n` 后统一提交）。
- 冲突：复用 `runConflictResolution` 的通用闭环（rebase/merge/cherry-pick 已共用）。
- 消息：默认 `revert: <原主题>`，支持多行表单 `form.TextInput` 编辑。

### P1-2 多行提交信息

- `pa`/`ps`/`am` 的消息输入改用 `form.TextInput`（本次 `sq` 已落地的多行表单），保留现有提交类型前缀校验与历史消息建议。
- 建议交互：先单行主题（带建议），再可选「补充正文」多行表单，避免所有提交都被强制走两屏。

### P2 查看类与 remote

- `status`：文件列表 + 选中文件展示 `git diff`（未暂存）/ `git diff --cached`（已暂存），只读、无副作用。
- `remote`：列表 + add/set-url/remove，写入前确认（复用 `form.Confirm`）。

### P3 收尾项

- `branch upstream`：`git branch --set-upstream-to`，复用远程分支列表（`GetRemoteBranches`）。
- `tag push`：推送全部本地缺失标签（`git push <remote> --tags`）与标签列表。

## 明确不做

`blame`、`bisect`、`submodule`、`sparse-checkout`、`gc/prune`、`archive` 等命令频率低，
且不符合 easyGit「工作流整合 + 交互式简化」的定位，保持交给原生 git。

## 维护约定

- 每实现一项，删除本文件对应条目并同步 `TODO.md` 与 README 双语命令表。
- 新增 Git 操作必须落在 `internal/gitcmd`（一操作一文件），UI 走 `internal/form`，文案走 `internal/i18n`。
