### 实施中发现并修复的问题(补录)

1. **stdin 共享缓冲 bug**:reset 双层列表场景(reset.go 先选提交再选模式)下,第二个列表读到 EOF。根因:每次 ListForm 调用各自 `bufio.NewScanner(os.Stdin)`,第一个 scanner 底层 Read 会提前吞掉后续输入。修复:`ListForm` 复用包级共享 `stdinBuf *bufio.Reader`,`runAccessibleList` 用 `ReadString('\n')` 逐行消费(Scanner 自持缓冲会重蹈覆辙);测试注入的 reader 走独立包装不受影响。EOF 语义:无内容且 EOF → 取消;数据+EOF(末尾无换行)先消费数据。
2. **parseCommitInfo 两个回归修复**(表格分列渲染的必要条件):单空格标签(如 set-language 的 `Soft 保留工作目录和暂存区`、push commit type 的 `fix 修复Bug等`、branch delete 的 `feature/login` 带空格标签)首词入 hash 列;无空格标签(如 `origin`)整体入消息列。均有 layout_test 回归用例。
3. **测试标签代表性取值**:merge strategy / rebase action 的标签由真实 i18n 文案拼接时,超长名称在 hash 列(8 宽)、超长说明在 60 列消息列(31 宽)被截断,整行匹配失败。与 cherry-pick 提交用例同先例,改用贴合列宽的代表性取值。
4. **visibleLabels 空白折叠**:表格分列渲染后单元格以填充空格相连,`strings.Fields` 归一化后再匹配(测试辅助函数)。

## API 设计(已批准)

```go
type ListKind int
const (
    ListSingle ListKind = iota // Enter 确认,返回 1 个值
    ListMulti                  // Space 切换,Enter 确认,返回全部选中值
)
// 默认不循环导航;需要 ↑/↓ 边界循环的命令用 ListFormWrap/NewListModelWrap
func ListForm(title string, options []config.Option, kind ListKind, preselected ...string) ([]string, error)
func ListFormWrap(title string, options []config.Option, kind ListKind, preselected ...string) ([]string, error)
func NewListModel(title string, options []config.Option, kind ListKind, preselected ...string) *listModel
func NewListModelWrap(title string, options []config.Option, kind ListKind, preselected ...string) *listModel
func StringOptions(strs []string) []config.Option
```

- 单选返回 `[]string`(values only,17 处调用点全部只用 value)。
- 预选:单选 cursor 落预选项;多选 selected 预填 + cursor 落首项。
- 键位语义:Esc/ctrl+c → 取消(`table.user.aborted`);q → 单选=取消、多选=确认当前选择;多选空确认 → `table.no.selection`;多选 space 切换。
- 循环导航:wrap=true 时 up/k 在顶部 → 跳末尾、down/j 在底部 → 跳回顶部(仅光标移动,不影响 q/enter/esc/space 语义);`len(m.choices) > 0` guard 防空列表负索引。默认 false,仅 pushAll.go(pa)显式开启。
- 帮助栏沿用 `selectHelpKeys`/`multiSelectHelpKeys`(已含 Esc)。
- 行渲染统一:显示串 = `opt.Label`;`Description != ""` 时拼 `opt.Label + " " + opt.Description`(纯文本,不嵌 ANSI);两行提交格式 label 不变。之后交 `parseCommitInfo`/`formatCompactCommit`/`SafeTruncate`。
- View 结构(≥6 行终端):单选与多选相同 = 标题+顶部线+表格行+底部线+帮助栏(n+4);多选标题行拼已选计数;单选仅标题。**<6 行终端单选仍只渲染表格行(零开销)**。
- accessible(TERM=dumb):`ListForm` 入口经 `isAccessibleMode()` 分流 `runAccessibleList`;纯文本 `N. label`(strip ANSI),stdin 行输入;单选序号、多选逗号分隔 `1,3`(空行=全不选);EOF → `huh.ErrUserAborted` 同义;非法输入报错重试。wrap 无 accessibility 概念(序号输入天然无边界)。

- **huh v2.0.3 accessible 内部实现(已查证,runAccessibleList 可照抄语义)**:
  - `accessibility.PromptInt(out io.Writer, in io.Reader, prompt string, low, high int, defaultValue *int) int`:循环打印 prompt → 读行 → `atoi` 校验范围,非法输出 `Invalid: must be a number between %d and %d`(low==high 时 `Invalid: must be %d`)并重试;空输入且有 defaultValue 时返回默认值。
  - `atoi`:TrimSpace 后为空返回 -1,否则 strconv.Atoi。
  - `Select.RunAccessible(w, r)`:打印标题(PaddingRight(1) 的 Title 样式,默认 "Select:"),逐行 `fmt.Fprintf(w, "%d. %s\n", i+1, option.Key)`(即 `N. label` 格式),PromptInt 取序号,取值后 return。多选项=空行时返回 -1 → `options[-1]` 会 panic,但我们自己的实现不受此限(空行=全不选)。
  - `Form.runAccessible` 在 form.go:721,timeout 不支持。
  - 输出流:all accessible 打印走传入的 `out io.Writer`;huh 框架层 `Form.Run()` 在 accessible 路径直连 `f.Form.Run()`(见 form.go Run 分支),最终 Select.RunAccessible 的 writer 由 huh 内部指定。**结论不变:本组件 runAccessibleList 自定输出流即可,建议 stdout(脚本管道兼容),TUI 路径 tea.WithOutput(os.Stderr) 不动。**
  - `PromptString`(L131):scanner 读行,EOF 时打印换行并 break(相当于放弃)。EOF 语义:我们实现里 EOF → 取消(ErrUserAborted 同义)更明确,不必照抄 break。`PromptPassword`(L108)用 term.ReadPassword,与我们无关。
