# 配置中心(config)

## 功能说明

所有可配置选项统一收敛到 `easyGit config` 一个交互式子命令。此前配置入口分散(`set-language`、`set-push-config`),且提交类型与标签版本上限**只有数据库默认值、没有任何配置 UI**。现在:

| 配置项 | 存储位置 | 旧入口 | 新入口 |
| ------ | -------- | ------ | ------ |
| 界面语言 | `settings` 表 `language` 键 | `set-language` | `config` → 界面语言 |
| 推送配置(仓库级) | `settings` 表 `push_remotes:<repo路径>` 键 | `set-push-config`(含 `clear`) | `config` → 推送配置 |
| 提交类型(pa/ps 的 commit type) | `options` 表(label/value/usage) | 无 | `config` → 提交类型 |
| 标签版本上限(tc 自动版本号封顶) | `patches` 表(prefix/major/minor/patch/suffix) | 无 | `config` → 标签版本上限 |

旧命令 `set-language` / `set-push-config` 已移除,全部收敛到 `config` 单一入口。

## 交互流程

```
easyGit config
```

主列表(单选,每项 Description 实时显示当前值摘要):

```
  配置中心
  ─────────────────────────────────────────
  ❯ 界面语言        当前: 简体中文
    推送配置        当前: origin, upstream
    提交类型        当前: fix, feat, refactor, …
    标签版本上限    当前: 999.9.9
  ─────────────────────────────────────────
  [↑/↓] 选择  [Enter] 配置  [Esc] 退出
```

- 选中某项 Enter → 进入子流程 → **完成后返回主列表**(循环,Esc 才退出)
- 语言切换后下一轮循环按新语言重建列表,即时生效
- 摘要读取失败优雅降级(如非 git 仓库时推送配置显示提示),不中断

### 子流程

1. **界面语言**:单选 en/zh(复用原 `set-language` 逻辑),保存后立即应用
2. **推送配置**:子菜单「设置推送配置 / 清除推送配置 / 返回」;设置 = 原 `set-push-config` 流程(多选远程),清除 = Confirm 确认后清空(原 `clear` 子参数并入菜单);非 git 仓库时进入该项提示不可用
3. **提交类型**:子菜单「添加 / 删除 / 返回」
   - 添加:`form.Input` 输入 → 格式校验(`^[a-z0-9-]+$`)+ 重复校验 → `config.AddCommitType`
   - 删除:`ListForm` 多选(每项 Description 显示 `使用 N 次` usage 统计)→ Confirm → `config.DeleteCommitTypes`;不允许删空全部类型
4. **标签版本上限**:`form.MultiInput` 自绘三列单页 5 字段(prefix/major/minor/patch/suffix,默认值 = 当前配置)
   - **行尾简介**:每行 = 标题列(定宽对齐) + 输入框(自适应) + 行尾弱化简介列——简介不混入标题、不占额外行(纵向空间有限时仍完整可读)
   - **矮终端友好**:无边框、无空行,8 行终端完整显示 ≈8 行(预览 1 + 字段 5 + 分隔 + 帮助);顶部预览行实时显示组合结果(如 `当前上限: v999.9.9`),任一字段输入即时刷新
   - **导航**:↑/↓/j/k 上下导航,Enter 逐字段推进/末字段提交,Shift+Tab 回退,Esc 取消;校验错误行内红色显示(替换行尾简介,不增行)
   - major/minor/patch 字段经 `InputSpec.Validate` 校验非负整数(表单层即时反馈);prefix/suffix 经 `AllowEmpty` 跳过非空校验(可留空;TERM=dumb 下空行 = 保留默认值)
   - 实现:`internal/form/multi_input.go`(自绘 tea.Model,不经 huh 渲染);tc 命令的版本号/提交消息两字段表单同用此组件

## 关键设计

### 自适应多列布局(列数不硬编码)

配置中心列表不固定列数,由 `ColumnSpec` 声明任意列,每列独立宽度策略:

```go
// internal/form/layout.go
const (
    ColumnAuto ColumnKind = iota // 自动宽度:按该列最长内容,可设 MaxWidth 上限
    ColumnFlex                   // 弹性宽度:占满剩余,可设 MinWidth 下限
)

type ColumnSpec struct {
    Title    string
    Kind     ColumnKind
    MaxWidth int // ColumnAuto 上限(0 = 不限)
    MinWidth int // ColumnFlex 下限(0 = messageColMin)
}
```

- 名称列 = `ColumnAuto`(最长名称完整显示不截断,仅超 `MaxWidth` 上限截断),摘要列 = `ColumnFlex`(占满剩余宽度)
- 多列支持:未来新增列(如使用次数、最近使用时间)追加 spec 即可,渲染/宽度计算自动适配
- 单元格来源:`config.Option.Cells` 非空时按列索引取值,否则取 `[Label, Description]`(向后兼容)
- 极窄终端(< 60 列)自动降级单列合并(全部单元格空格连接)
- 入口:`form.ListFormColumns` / `form.NewListModelColumns`;`CalculateAdaptiveColumns` 计算列宽
- 配置中心所有列表(主列表、推送/提交类型子菜单、删除多选、语言选择)统一走此路径

### 提交类型管理错误处理(审查修复)

- 重复/格式校验统一在 `config.AddCommitType`(单一事实来源),命令层用 `errors.Is(err, config.ErrCommitTypeExists)` 映射本地化文案,真实错误(如 DB 故障)原样带出,不再显示误导性的"获取选项失败"
- 新增 i18n 键 `error.add.commit.type` / `error.delete.commit.type`(带 err 细节)
- 哨兵错误 `config.ErrCommitTypeExists`

### TERM=dumb(accessible)输入源修复

发现并修复一个既有 bug:管道脚本场景(TERM=dumb)下列表表单经共享 `stdinBuf` 读取,但 huh accessible 的 Input/Confirm/MultiInput 直接读 `os.Stdin` —— 列表的 bufio 预读会吞掉后续输入,导致 `pa`(列表→输入)等流程在脚本管线中读不到输入。

修复两层:
1. `newForm` 在 accessible 模式统一 `f.WithInput(stdinBuf)`,所有表单共用同一缓冲
2. `lineReader` 包装共享缓冲:huh 内部 `PromptString` 每次新建 `bufio.Scanner`,Scanner 会预读大块数据到私有缓冲;MultiInput 多字段场景下前一字段的废弃 Scanner 会吞掉后续字段的输入(实测标签版本上限 5 字段只有第 1 个字段生效)。包装后每次 `Read` 至多返回一行,Scanner 消费一行后内部无残留

另有:accessible 单选列表预选项附加 `(current)` 标记(`form.accessible.current` 键),替代 TUI 光标落位。
